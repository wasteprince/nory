# NORY — Windows 11 x64

В 0.3.3 используется Rust-бэкенд и локальный интерфейс Vue + TypeScript + Tailwind
в Tauri/WebView2. Старый GTK-runtime не входит в установщик. .NET, Node.js и
MSYS2 на компьютере пользователя не нужны.

## Установка

Откройте `NORY-0.3.3-windows-x64-setup.exe`, подтвердите запрос Windows и
дождитесь окончания установки. Приложение устанавливается в
`C:\Program Files\NORY`; путь может отличаться на другом системном диске.
Запускайте NORY обычным способом из меню «Пуск» или с рабочего стола.

Поддерживается только Windows 11 x64 (build 22000+). Windows 10, Server и
ARM64 не входят в эту сборку. Установщик не выключает антивирус, брандмауэр,
Secure Boot, целостность памяти и не изменяет системный HTTP-прокси.

## Что входит

- Xray 26.3.27, sing-box 1.13.18, Mihomo 1.19.30 (`amd64-compatible`).
- Официальный подписанный Wintun 0.14.1 и GeoData.
- Локальные ресурсы интерфейса и загрузчик WebView2 Microsoft. Если runtime
  отсутствует, для его установки нужен интернет.
- **251 флаг внутри `nory.exe`, только в Windows-сборке.** Флаги не требуют
  эмодзи-шрифта или сети. В Linux остаются системные флаги.
- Если в названии узла нет emoji, распространённые названия городов (например,
  Paris/Париж) также получают флаг из встроенного набора.
- Системный шрифт Windows, векторные значки интерфейса, тёмная панель окна.
  Используется стандартное GPU-ускорение WebView2.

## Подключение и права

Выбор: TUN через Xray + sing-box либо TUN через Mihomo. Режима системного
прокси нет. Служба `NoryTunnel` устанавливается один раз с правами
администратора, но запускает TUN только по запросу клиента. Интерфейс
приложения работает с обычными правами.

Для **Xray + sing-box** при первом подключении в запущенном NORY требуется
подтверждение администратора через UAC. Повышается только установленный helper,
не окно WebView2. Служба проверяет его токен и выдаёт доступ конкретному процессу
NORY до его завершения. После перезапуска приложения подтверждение нужно снова;
при отмене запроса Xray TUN не запускается. Для Mihomo эта дополнительная
авторизация не требуется. Linux это изменение не затрагивает.

Одна служба владеет одним TUN-ядром; отключённый Wintun-интерфейс считается
остатком предыдущей сессии и переиспользуется, а активный или чужой интерфейс
остаётся защищённым. Переключение сначала останавливает
предыдущее. Сеанс другого пользователя нельзя перехватить. Выход/аварийное
завершение клиента останавливает его ядро; очистка затрагивает только маршруты
его TUN-интерфейса. Закрытие окна в трей не завершает клиент.

При отключении служба подтверждает завершение своего дерева процессов и очистку
маршрутов. При ошибке клиент сохраняет возможность повторить отключение. Команда
выключения во время запуска ставится в очередь и отменяет автопереподключение.
`NoryTunnel` остаётся работающей службой-посредником без активного TUN — это нормально;
`xray.exe` и TUN-ядро после успешного отключения не должны оставаться запущенными.

Поиск процессов и приложений использует Unicode API Windows, включая
32- и 64-битные разделы реестра. Если приложения нет в реестре, выберите
запущенный процесс или укажите `.exe` вручную. Счётчики трафика читаются через
IP Helper, ICMP-пинг делает пять запросов, отсутствующий ответ — `n/a`.

Подписки и HWID сохраняются в пользовательском AppData. Удаление приложения
не удаляет эти данные. Перед ручным обновлением закройте NORY через трей.
Встроенное обновление проверяет Ed25519, SHA-256 и размер установщика,
запрашивает подтверждение Windows и открывает клиент после установки.

## Проверки и ограничения

Сборка выполняется на Linux с MSVC SDK и статической CRT. Проверены компиляция
GUI/helper и упаковка NSIS, зависимости и ресурсы. Интерфейсные тесты используют
mock IPC. Реальный запуск на Windows 11 и VPN-соединения в этом выпуске не тестировались.
Это **не проверка настоящего Wintun, WFP, сна/пробуждения, обхода UDP в играх
или UAC обычного пользователя на Windows 11**. Известная ошибка Xray без её
диагностики не объявляется исправленной переходом с GTK на WebView2.

Системная служба принимает встроенные узлы/группы Mihomo, но отклоняет
конфигурации с внешними file/proxy/rule providers, скриптами и файлами ключей.
Она никогда не исполняет ядро из пользовательского каталога: системные ядра
обновляются вместе с установщиком. Возможности протоколов двух ядер различаются.

У установщика нет Authenticode-сертификата издателя; подпись обновления
Ed25519 не заменяет Authenticode. Предупреждение Windows о неизвестном
издателе возможно. Не отключайте системные средства безопасности.

## Диагностика

Сообщения подключения доступны на странице «Логи». Диагностические флаги
`--check-runtime` и `--check-service` относились к старой GTK-сборке и не поддерживаются
новым GUI. Ошибки запуска TUN-ядра: `%ProgramData%\NORY\runtime\core.log` (доступ
администратора). Удаляйте пароли, UUID и адреса подписок перед передачей логов.
